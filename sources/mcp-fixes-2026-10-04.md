## What changed

- **Redaction:** the IBAN detector uses registered country prefixes, and the card detector uses token boundaries. Generated alphanumeric IDs are no longer turned into bank details. PII checks were not disabled; regression tests preserve checks for real IBAN, card and email forms. The source of the prefix list is [SWIFT Registry, release 101, §2](https://www.swift.com/sites/default/files/files/iban-registry-v101.pdf). This is a fixed list, not a claim of full coverage of all subsequent revisions or a bank account check.
- **Malformed response:** a typed transport response reaches the existing validator of the published Gate schema. When a receipt is absent, one read-only probe is performed: only a confirmed receipt of the corresponding operation/run allows `succeeded + withheld`; without proof it remains `outcome_unknown`. There is no new business dispatch. Schema error details with raw content are not exposed to the client.
- **Fence:** the Make command accepts a Gate UUID, resolves a separate upstream ID and run, and verifies the service correspondence. Gate confirms the fence via an authenticated status endpoint. An already executed commit ends as succeeded, not no_effect. The upstream ID is now written durably before network dispatch.
- **Reset:** the force bypass of unresolved was removed; an unavailable service stops the reset with closed admission. All unfinished operations without a page limit and the run IDs of all three services are checked. Claim and admission closing use a shared lock, so a stale request does not slip through after closing.
- **Test isolation:** `make demo-mcp-test` by default creates a temporary Compose project, its own volumes and a random loopback port; after completion it deletes only those, leaving the evidence. Changing the rehearsal state is possible only through an explicit `DEMO_MCP_TEST_IN_PLACE=1`.
